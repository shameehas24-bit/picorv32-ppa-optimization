# PPA Optimization of PicoRV32 Using RTL-Level Techniques

RTL-level area/timing/switching-activity study of the [PicoRV32](https://github.com/YosysHQ/picorv32)
RISC-V core (ISC license, see `LICENSE`). The original and optimized RTL are kept side by side and run
through the same open-source flow so the comparison is fair.

```
rtl/orig/picorv32.v   unmodified upstream core
rtl/opt/picorv32.v    optimized core (generated by scripts/apply_opts.py)
rtl/picorv32_ppa.patch  diff orig -> opt
scripts/apply_opts.py selectable RTL edits (E1..E4)
scripts/run_flow.sh   synthesis + P&R + gate-level sim for one variant/config
scripts/toggles.py    switching-activity counter (VCD)
scripts/fmax_top.v    I/O-reducing wrapper used only for the Fmax run
sw/, tb/              benchmark program (sort + CRC32) and self-checking testbench
results/              raw per-run output
```

## Optimizations (what was actually changed)

| ID | Change | Target | Kept? |
|----|--------|--------|-------|
| E1 | One shared subtractor produces both signed and unsigned less-than (was two comparators) | Area | yes |
| E2 | One shared right shifter for left and right shifts (bit-reverse in/out, wiring only); applies when `BARREL_SHIFTER=1` | Area | yes |
| E3 | Carry-gated 64-bit cycle/instruction counters | Power | no, no measurable gain |
| E4 | Hold ALU result registers once latched | Power | no, no measurable gain |

E3 and E4 are still available in `scripts/apply_opts.py` (`python3 scripts/apply_opts.py rtl/orig/picorv32.v out.v E1,E2,E3,E4`).

## Flow and metrics

* **Area**: Yosys generic gate mapping (`synth -flatten; abc -g AND,NAND,OR,NOR,XOR,XNOR,MUX`) cell count, and iCE40 LUT4 count (`synth_ice40`).
* **Timing**: topological logic depth (`ltp`), and post-place-and-route Fmax on iCE40 HX8K with nextpnr, 5 seeds (average reported; seed-to-seed spread is about +/-4 MHz).
* **Power (proxy only)**: bit toggles of every net in the gate-level netlist during the benchmark, per cycle. This is relative switching activity, **not** absolute power. Real power needs a liberty library and a power tool.
* **Correctness**: every run executes the same program; result, memory-write hash and cycle count must match the original.

Reproduce: `bash scripts/run_flow.sh orig default 0; bash scripts/run_flow.sh opt default 0` (and `... barrel 1`).
Needs: yosys, iverilog, nextpnr-ice40, python3. Rebuild the benchmark with `riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32` (see `sw/`).

## Results (benchmark: sort + CRC32, 20k cycles)

| Config | Metric | Original | Optimized | Change |
|---|---|---|---|---|
| default | Gate cells | 7610 | 7624 | +0.2% |
| default | iCE40 LUT4 | 1678 | 1652 | -1.5% |
| default | Logic depth | 65 | 65 | 0 |
| default | Fmax avg (MHz) | 66.2 | 62.4 | -5.6% (within noise range) |
| default | Toggles / cycle | 348.9 | 350.8 | +0.5% |
| barrel shifter | Gate cells | 7738 | 7628 | -1.4% |
| barrel shifter | iCE40 LUT4 | 1850 | 1726 | -6.7% |
| barrel shifter | Logic depth | 63 | 63 | 0 |
| barrel shifter | Fmax avg (MHz) | 64.4 | 61.2 | -5.0% |
| barrel shifter | Toggles / cycle | 347.9 | 347.1 | -0.2% |

Functionally identical in all runs (`RESULT=e9ad7dac HASH=7dd73236`, same cycle counts).

## Honest conclusions

* Sharing logic saves area: about 7% of LUTs with the barrel shifter, about 1.5% in the default config.
* It costs a little timing: the extra mux level lowers average Fmax by roughly 5%. Run-to-run placement noise is large, so treat this as a trend.
* No meaningful change in switching activity. E3/E4 (power-oriented) did not help, and a single workload with an equal-weight toggle proxy cannot resolve small power effects.
* Not done: real power analysis (needs a PDK/liberty), ASIC timing, the formal equivalence check, and the upstream riscv-tests regression. Run those before claiming a production-ready change.
